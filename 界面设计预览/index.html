📐 界面布局说明

🗂整体布局结构

采用 Windows 桌面应用常用的三段式布局（顶部标题栏 + 左侧导航 + 主内容区），从上到下、从左到右层次分明：

① 标题栏 (52px)
② 侧边导航 (220px)
③ 主内容区 (自适应)

各区域功能

  • 标题栏：左侧应用图标与标题，右侧主题切换按钮（醒目位置，一键切换日/夜模式）与标准窗口控制（最小化 / 最大化 / 关闭）
  • 侧边导航：6 个主功能入口（抓取工作台、爬取历史、死书清单、站点管理、运行日志、远控），底部状态栏显示实时运行状态
  • 主内容区：承载各页面核心功能，内边距 20px，页面间距 20px，呼吸感充足

🔗层级关系与交互逻辑

页面层级（从高到低）

  • L0 全局层：标题栏 + 侧边导航 + 状态栏，始终可见，跨页面共享
  • L1 页面层：6 个主页面通过导航切换，使用 Stack 模式保活状态
  • L2 卡片层：功能模块以卡片为单位组织，卡片内包含标题栏 + 内容区
  • L3 抽屉/浮层层：右侧详情抽屉、对话框、提示条，上下文相关
  • L4 行内展开层：表格行内展开详情，不打断浏览流

核心交互流

  • 抓取流程：输入URL → 选择模式 → 点击开始 → 任务出现在表格 → 实时进度/日志更新 → 完成后状态变更
  • 任务联动：点击行选中 → 日志条自动切换到该任务日志 → 右侧抽屉同步显示详情
  • 页面切换：点击侧边导航切换页面，抓取任务在后台持续运行

📐设计系统规范（本轮重构）

本轮把原先散落在各处的硬编码值收敛为一套令牌，落地时按本节实现即可，无需再逐页对色。

色彩令牌三层架构

旧稿最大的结构性问题是「品牌色 = 功能色 = 文字色」三者共用一个变量（名为 --accent-blue，值却是橙色），必然出现"改一处崩一片"。现拆为三层：

  • ① 品牌层 --brand / --brand-hover / --brand-subtle： 纯色值，只用于大色块、图形、进度，不承载文字
  • ② 可读层 --accent-fg / --on-brand-subtle / --btn-primary-fg： 「压在品牌色上的文字」，各自保证 ≥4.5:1
  • ③ 功能层 --status-* / --on-accent-*-light： 状态语义，每组拆前景 / 底 / 描边三件套

落地对应：Flet 侧把三组值写成 ui_theme.py 里的模块级常量， 组件只引用语义名（如 ACCENT_FG），不再出现字面色值。

间距与圆角

  • 间距：4px 栅格，--sp-1 4 → --sp-2 8 → --sp-3 12 → --sp-4 16 → --sp-5 20 → --sp-6 24 → --sp-7 28 → --sp-8 32 → --sp-10 40
  • 圆角只留 4 档 + 胶囊：sm 4（控件）/ md 6（卡片内小方块）/ lg 8（卡片）/ pill 999（胶囊）
  • 本轮修正：旧稿 lg 与 xl 同为 8px、md 与 sm 仅差 1px， 组件各取各的 ⇒ 视觉噪声。现在每个值都有唯一用途

交互状态（每种都必须有，不许只做 hover）

  • 按钮：hover / active / focus-visible / disabled 四态齐全，主/次/危险/幽灵四类各一套
  • 图标按钮：额外有 .danger 危险态与 [aria-disabled] 同步禁用态
  • 禁用态：pointer-events:none + cursor:not-allowed + opacity:1（不用降低透明度，避免连带文字也看不清）
  • 焦点环：统一 outline:2px solid var(--focus-ring); outline-offset:2px， 仅 :focus-visible 时出现，鼠标点击不显示
  • 胶囊选中态：浅底 + 深字 + 描边，不用实心块压白字

↕️全局滚动条规范

边界条件（避免双滚动条 / 横向抖动）

  • 用 overflow:auto（非 hidden/scroll）⇒ 滚动条仅在内容溢出时出现
  • 横滚容器另设 .scrollable-x：overflow-x:auto + overflow-y:hidden，纵向交还父容器
  • scrollbar-gutter:stable 预留轨道 ⇒ 滚动条出现时不引起内容位移，无横向抖动
  • 单一轴单一责任：每个轴只允许一个滚动容器，父容器与子容器不得同轴双滚
  • 外层 .app-body 固定 overflow:hidden，杜绝页面级滚动与内容级滚动打架

交互支持

  • 滚轮 / 触摸板：原生行为，无需额外代码
  • 拖拽：::-webkit-scrollbar-thumb 默认可拖；Firefox 走 scrollbar-width
  • 键盘：滚动容器带 tabindex="0" + role="region" + aria-label，Tab 可聚焦，方向键/PageUp/PageDown/Home/End 原生生效，焦点环为 2px 内描边
  • 双端样式：Chromium 走 ::-webkit-scrollbar，Firefox 走 scrollbar-width:thin + scrollbar-color

尺寸与配色

  • 滑块 10px（细滑块 + 透明轨道），圆角 5px，border:2px solid transparent + background-clip:content-box 做内缩
  • 默认 --border-medium，悬停 --text-quaternary（与现有 UI 规范同源）
  • 触屏（pointer:coarse）加粗到 12px 并提亮，保证拖拽命中区

小屏断点表现

实机窗口下限 min_width=960，桌面端不会更窄；设计稿仍留三档以验证退化不崩坏：

  • ≤1100px：收窄留白与间距，不碰 overflow
  • ≤960px（实机下限）：滚动条收窄到 8px，横滚容器内边距 4→2px 让出可视宽；底部状态栏 flex-shrink:0，永不遮挡内容
  • ≤720px：侧栏退化为 56px 图标条（Star 提示行隐藏，GitHub 图标仍可点、仍有焦点环），主内容单列

断点原则：只调宽度/字号/间距，绝不新增滚动容器，因此任意断点下纵向都只有 1 个滚动容器。
