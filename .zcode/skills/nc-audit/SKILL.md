# 小说爬虫审查流程

本项目的审查按**域并行派发只读 Explore 子智能体**,主会话只做汇总与抽查验证。
全文约 2 万行,不适合主会话逐行读。

## 1. 派发 (并行, 一次消息多个 Agent 调用)

按域拆 3~4 个 Explore 子智能体, 每个 prompt 必须自包含 (子智能体看不到本会话):

| 域 | 覆盖文件 |
|---|---|
| 核心引擎 | 源码/爬虫.py (7000行,重点类结构/超长方法/并发共享状态)、请求引擎、反爬检测器、速度自适应、代理池、风控事件、站点漂移检测、dns_doh |
| GUI + 站点适配 | gui_app.py、gui_components/**、sites_config.py、site_probe.py、站点适配/*.py |
| 辅助 + 工程 | 质检器/content_decoder/decrypt_utils/captcha/waf_captcha/browser_driver、历史/书架/epub、日志、测试/、脚本/、.github/、build_exe、requirements |

每个子智能体的报告要求 (写进 prompt):
- 架构职责简述 + 优点 + **问题清单 (文件:行号 + 描述 + 高/中/低)**
- 明确检查点: 线程安全 (无锁 RMW/懒初始化竞态)、资源泄漏、裸 except 吞异常、
  原子写、SSRF 校验遗漏、硬编码密钥 (api_key/secret/password/token)、死代码
- 不贴大段代码, 结论性输出

## 2. 抽查验证 (主会话亲自做, 不可省)

子智能体会误报。对每个"高"级发现,主会话必须 `Read`/`grep` 对应 行号 亲自确认
逻辑成立后再写进结论;确认不了的降级或剔除。抽查用 `sed -n`/`grep -n` 即可。

## 3. 分级口径

- **高**: 可复现的功能性 bug / 数据损坏 / 发布流程断档 / 安全默认值漂移
- **中**: 并发竞态 (当前休眠或影响有限) / 性能反模式 / 配置与代码不一致
- **低**: 死代码 / 文档漂移 / 风格问题

## 4. 产出

- 报告写入 `文档/项目审查报告-{YYYY-MM-DD}.md` (沿用既有报告结构)
- 每条问题给出 修复建议 + 一行到几行的预估工作量, 按"还债优先"排序
- 修复后回填台账状态 (已修/未修), 防止下轮重复报告

## 5. 本项目已知的历史病灶 (审查时重点关注是否复发)

- 爬虫.py 上帝类 + 约 200 处站点域名硬编码特判 (应迁注册表/插件)
- 实例级计数器/UA 无锁读改写 (并发下失真)
- GUI 以 print 正则解析作数据通道 (爬虫改文案即静默失效)
- flet 版本约束与实际 API 世代不符
- 质检权重在 Python 常量与 rust_core_poc/pyo3_ext/src/lib.rs 双处维护 (改一边必须同步另一边并跑 qa_parity.py)
