# 验证码模块使用说明

模块文件：`源码/captcha_module.py`（独立可插拔，与核心爬取逻辑解耦）
配置文件：`配置/captcha_config.json`（首次运行自动生成，可热重载）

## 一、设计原则：规避优先，识别兜底

```
请求 → 规避策略(频率控制/UA轮换/Cookie维持/IP轮换) → 正常页面 ✓
   ↓ 触发验证码
分级识别链 → 人工兜底
```

- **规避优先**：通过请求频率控制、指纹伪装、Cookie 维持、IP 轮换（代理池）、
  接口替换（备用端点）等策略**降低验证码触发率**，这是第一道防线
- **识别兜底**：仅在规避无效、页面已返回验证码时才启用识别能力

## 二、分级处理链（自动选择）

| 验证码类型 | 首选方案 | 成本 | 兜底 |
|---|---|---|---|
| 简单字符验证码 | ddddocr 本地识别 | 0 元 | 人工输入 |
| 滑块验证码 | OpenCV 缺口定位 + 拟人轨迹 | 0 元 | 人工输入 |
| reCAPTCHA / hCaptcha / Turnstile | 第三方打码平台 API | 约 0.03 元/次 | 人工输入 |
| 点选/语义验证码 | 可配置多模态模型（接口占位） | 按模型 | 人工输入 |

策略链按 **零成本优先** 排序：ddddocr → slider → 第三方平台 → 点选 → 人工。

## 三、配置（captcha_config.json）

识别能力**默认全部关闭**，需手动开启：

```json
{
  "strategies": {
    "ddddocr":     { "enabled": true },   // 开启本地字符识别
    "slider":      { "enabled": true },   // 开启滑块识别
    "third_party": { "enabled": true },   // 开启打码平台
    "point_click": { "enabled": true }    // 开启点选(未配模型时转人工)
  },
  "retry_limit": 3,                        // 识别失败重试上限
  "monitor": {
    "rate_alarm": 0.5,                     // 触发率异常告警阈值
    "balance_warn": 5.0,                   // 打码平台余额预警(元)
    "log_path": null                       // 事件日志(JSONL), 填路径即启用
  },
  "third_party_api": {                     // 打码平台参数(自行填写)
    "provider": "", "api_key": "", "submit_url": "", "poll_url": "", "balance_url": ""
  },
  "avoidance": {
    "base_delay": 1.0,                     // 基础请求间隔
    "proxies": [],                         // 代理池: ["http://ip:port", ...]
    "cookie_dir": null                     // Cookie 持久化目录
  }
}
```

**热切换**：修改配置文件后，下次验证码处理自动生效（每次调用读取最新配置），无需重启爬虫。

## 四、监控与容错

- 每次验证码处理记录：**类型 / 耗时 / 成功率 / 成本**
- 抓取结束时自动输出统计报告（`manager.report()`）
- 告警：触发率异常（建议降速）、连续失败达上限、打码平台余额不足
- 事件日志可落盘为 JSONL（配置 `monitor.log_path`），便于后续分析优化

## 五、打码平台接入（可无缝替换）

`ThirdPartyCaptchaHandler.Provider` 抽象了平台接口，替换平台只需：
1. 继承 `Provider` 实现 `submit / poll / balance` 三个方法
2. 在 `build_manager()` 或配置中切换 Provider

内置的 `HttpApiProvider` 适配多数平台的通用 HTTP API（填 submit_url/poll_url/balance_url 即可）。

## 六、与爬虫的集成

爬虫 `NovelSpider` 初始化时自动加载模块；tanmixs 等 Selenium 站的验证码处理
自动走"自动识别链 → 人工兜底"。模块加载失败时降级为内置人工流程，不影响主功能。

## 七、安全与合规边界

- 自动识别绕过网站 WAF 验证码存在法律风险，详见《验证码模块合规评估.md》
- 识别能力默认关闭，请仅在个人学习/自动化测试场景使用，自行评估风险
- 第三方打码平台需自行承担成本与合规责任
- 人工辅助流程（manual）始终可用，等价于人类正常访问
