## 二、高严重度

### G-H1. 弹窗文字缺显式色值（v2.4.19 同类，EXE-only 显现）

v2.4.19 教训：打包 EXE 中 AlertDialog 文字不显式设 color 会渲染成不可见
（Flutter 侧 dialog 主题缺色，源码模式正常）。当时只修了关闭确认弹窗
（gui_app.py:643-656 全部显式 `MORANDI_ON_SURFACE`），**其余弹窗漏网**：

1. **删除任务确认框** [task_table.py:374-388](file:///e:/程序文件/小说爬虫/源码/gui_components/task_table.py#L374-L388)：
   ```python
   title=ft.Text("删除任务"),                    # 无 color
   content=ft.Text(f"任务输出文件:\n{fname}\n\n是否同时删除本地文件?", ...)  # 无 color
   ```
   **加重因素**：这是"是否同时删除本地文件"的确认弹窗 —— EXE 里用户看不到
   提示文字，只剩三个无上下文按钮，"同时删文件"误点风险直接落地。

2. **新建适配器弹窗** [site_manage_page.py:537-548](file:///e:/程序文件/小说爬虫/源码/gui_components/pages/site_manage_page.py#L537-L548)：
   `ft.Text("新建适配器模板")` 同样无色（TextField 有 text_style 但无色）。

**修复**：按 gui_app.py 关闭弹窗的写法补 `color=MORANDI_ON_SURFACE`（或统一走
`ui_fluent.txt()`）。修完必须在**打包 EXE** 里人工双验（源码模式看不出）。
**防回归建议**：G-M1 修复时顺手在 `open_dialog()` 加断言/告警——AlertDialog
子树里存在无色 ft.Text 时打日志（运行时拦截，比事后冒烟可靠）。

### G-H2. 全权限 token 随推送外发第三方

[服务.py:456](file:///e:/程序文件/小说爬虫/源码/远控/服务.py#L456)：
```python
链接 = f"\n阅读: {前}/reader/{bid}?k={取配置().get('token','')}"
```
任务终态推送（Bark/ntfy）正文里内嵌**全权限 token**。用户配置了"外链前缀"
（Tailscale serve 场景）+ 推送通道时，token 离开本机：
- ntfy 公网服务：任何能看到该推送频道的人即得 token；
- Bark 默认自建相对可控，但推送正文仍过第三方 APNs 链路。

token 可操作任务/读文件/删任务（服务.py 全部 API 同一 token）。

**修复**（选一）：
- 推送正文不带 `?k=`，改为提示"打开面板查看"（面板本就有 token）；
- 或服务端为阅读链接生成一次性/短时 ticket（`/reader/{bid}?t=xxx`，5 分钟有效，
  服务端 map 校验）。

## 三、中严重度

### G-M1. 弹窗开/关 API 不对称 → overlay 残留

[ui_fluent.py:274-293](file:///e:/程序文件/小说爬虫/源码/gui_components/ui_fluent.py#L274-L293)：
- `open_dialog`：优先 `page.show_dialog(ctrl)`（flet 0.86 新 API，压入 dialog 栈）；
- `close_dialog`：`ctrl.open = False; page.update()`（0.21 时代旧式）。

`show_dialog` 挂进 dialog 栈的实例，正确关闭是 `page.pop_dialog()`
（gui_app.py:592 `_弹层关闭` 即正确示范）。旧式 `open=False` 对栈上弹窗
可能不摘除 → task_table 删除框（:381/:393）与 site_manage_page 新建框
（:543/:554）点"取消"后 overlay 残留、反复开关累积。

**修复**：`close_dialog` 改为对称的 `page.pop_dialog()` + 兜底旧式，
一处改动三个弹窗受益。

### G-M2. 远控面板日志 DOM 无上限累积

[面板.html:164-166](file:///e:/程序文件/小说爬虫/源码/远控/面板.html#L164-L166)：
每 1.5s `appendChild(textNode)` 只增不删，仅切任务（:146）或服务端截断
（:158）才清空。长任务挂机一晚，浏览器内存持续增长（服务端虽 500 条截断，
**客户端**收过的全留着）。

**修复**：append 前检查 `box.childNodes.length > 2000` 则丢弃头部
（或定期重建 textContent）。

### G-M3. 站点配置热重载与抓取线程竞态

[sites_config.py:425-486](file:///e:/程序文件/小说爬虫/源码/sites_config.py#L425-L486)：
`reload_runtime_config()`（GUI 保存配置时调，无锁）执行
`SITE_PATTERNS[:] = [...]` 与 `for _p: _p.pop('enabled')` 原地改列表，
而爬虫工作线程并发调 `get_site_pattern()` 遍历同一列表 ——
GUI 保存与抓取并发时，worker 可能读到瞬时空表（该请求按无适配站点处理）
或丢 enabled 标志。窗口极小但真实存在。

**修复**：热重放进 `threading.Lock`，或改为"构建新列表后原子换引用"
（`SITE_PATTERNS = 新列表` + get 侧读模块属性）。

### G-M4. 站点配置保存非原子 + 失败静默回退

[site_manage_page.py:204-228](file:///e:/程序文件/小说爬虫/源码/gui_components/pages/site_manage_page.py#L204-L228)：
`write_text` 直写（与增量审查 M2 同源），且失败路径 `except: 记日志+return False`
—— 但**文件写一半损坏**的场景下次启动 `_apply_runtime_config` 解析失败
静默回退内置 SITE_PATTERNS，**用户全部自定义站点消失且无任何提示**。
GUI 侧 `:1160` 导出同样直写（且未过 `_json_clean`，含函数字段时直接 dumps 抛错）。

**修复**：tmp + `os.replace`（参照 爬取历史.py）。

## 五、已核验无问题

| 维度 | 结论 |
|---|---|
| **XSS** | 面板/阅读.html 全部 `textContent`/`createTextNode`（面板.html:116 有明确注释），全仓无 innerHTML/insertAdjacentHTML；服务.py 响应均为 JSON/FileResponse |
| **路径穿越** | 书籍端点经 md5 id 反查扫描结果（服务.py:186-194），路径不接用户输入；适配器创建 domain 清洗 + resolve 前缀双保险（site_manage_page.py:562-568） |
| **SSRF** | 远控提交 URL 过 `validate_public_url`（服务.py:232-233） |
| **线程纪律（主链路）** | `_run_task`/`TaskLogRedirector` 只写 TaskInfo 数据；托盘菜单回调（pystray 自建线程）经 `page.run_task` 转发回事件循环，正确；远控线程注入任务只写数据由轮询呈现 |
| **window 属性 update** | `_显示主窗`/`_隐藏到托盘` 均显式 `page.update()`（v2.4.19 修复在位）；初始赋值先于 page.add 无需 |
| **run_task 一致性** | 全部异步动作经 run_task；无同步回调内 await/漏 await |
| **鉴权覆盖** | 除设计内免鉴权的 `/` 与 healthz 外，全部 API + reader 页覆盖 `_要求鉴权`；代码不打印 token；uvicorn warning 级日志不落 query |
| **服务端内存** | `_已推终态` 500 键上限（服务.py:462-465）、`_章节缓存` 8 本上限 |
| **GUI 列表截断** | 任务日志 500 条原地截断；history URL 明细 500 双重截断；tasks dict 由用户删除清理（设计如此） |
