## 1. 项目背景与定位

### 1.1 一句话定位

**面向个人用户的 Windows 桌面小说爬虫**：输入小说目录页 URL，自动完成
「抓目录 → 抓正文 → 反爬对抗 → 解码清洗 → 语义质检 → 导出 txt/EPUB」全链路，
配 Flet 桌面 GUI、手机浏览器远控、CLI 批量三种入口，打包成单文件 EXE 分发。

### 1.2 项目性质与演进

个人学习研究型项目（非商业产品），Python 约 2.2 万行 + Rust PyO3 扩展。
开发模式为**多 AI 会话交替接力**（zCode / WorkBuddy / Claude / 千问工作助理 / Trae），
以 `HANDOFF.md` 为跨会话唯一事实来源。版本节奏极快：v2.4.16（09-11）→ v2.4.30
（09-27）两周内 14 个版本，主要由"用户实测反馈 → 日志取证定位 → 修复 + 回归用例"驱动。

### 1.3 合规边界（硬约束，任何改动不得突破）

- 仅供个人学习与技术研究，禁止商业用途；抓取内容版权归原作者，建议下载后 24 小时内删除
- **验证码自动识别（ddddocr）分发模板与代码默认必须关闭**；所有自动识别路径在未开启时
  必须显式拒绝并转人工兜底
- 用户可在**自己机器**的配置中显式开启（`captcha_config.json` 的 `strategies.dddddocr.enabled`）
  —— 该选择不属于配置漂移，后续会话**勿当问题修回去**
- 一切用户可控 URL 发请求前必须过 `validate_public_url`（SSRF 防线）
- 遵守目标网站 robots.txt 与服务条款，合理控制频率（速度自适应 + 同域闸门即为此设计）

### 4.2 进程模型（关键认知：flet 是双进程）

桌面客户端 = **Python 进程**（协议服务端 + 爬虫线程 + 内嵌远控 uvicorn）
+ **flet.exe 客户端子进程**（Flutter 渲染）。三条推论：

1. Python 侧 `os._exit()` 会留下**孤儿窗口**（界面还在、点关闭没反应）→
   退出必须走 `gui_components/退出流程.py` 的 `执行退出()`，**7 步顺序不可改**
2. 内嵌远控随 Python 进程常驻：**客户端开着 = 远控服务在**（默认 8760）
3. 强杀进程须连同 flet.exe 一起清（残留会致新实例永远 Working）

**桌面客户端与独立远控服务同时开**会争抢 8760 端口（后启动方失败仅记日志）；
两者任务列表**相互独立**，但书架/历史/检查点等数据文件共享安全（原子写）。

### 4.3 线程模型

| 线程 | 持有状态 | 同步手段 |
|---|---|---|
| GUI 主线程 | TaskManager（单一数据源） | GIL + 1s 轮询子树 update |
| 爬虫 worker（1~8/任务） | 每线程独立 Session | 引擎会话缓存锁 + 速度闸门 Condition + 同域闸门 |
| 事件通道 | 按 contextvars 隔离 | 随 `copy_context` 传播到 worker（H1 修复史） |
| 内嵌远控 uvicorn | 共享 TaskManager 只读快照 | GIL 下 dict/list 读安全 |
| 托盘 pystray | 自有消息循环 | 回调经 `page.run_task` 回 UI 线程 |

**线程纪律**：爬虫工作线程只写数据结构，**绝不碰 Flet 控件**；共享可变状态加锁或放 thread-local。

## 5. 技术栈与依赖关系

### 5.1 技术栈

| 层 | 选型 |
|---|---|

| 测试 | unittest 发现式（353 项）+ 手写回归（41 项）+ 黑盒 E2E 冒烟 |
| CI | GitHub Actions：test.yml（门禁，可 workflow_call 复用）+ release.yml（tag 触发构建发布） |

### 5.2 依赖管理（双文件制）

- `requirements.txt`：**意图声明**（`>=` 版本范围，flet 有上界）
- `requirements-lock.txt`：**75 包精确钉版**，pip constraints 格式；生成/校验/幂等由
  `脚本/gen_lock.py` 负责，**升级依赖后必须重跑刷新**
- CI 两个 workflow 均以 `pip install -c requirements-lock.txt` 接入（离线校验 21 需求 0 不一致）

### 5.3 模块依赖方向（单向，无环）

```
入口层 (gui_app / 启动器 / 远控.__main__)
   ↓
编排层 (task_manager / 任务事件 / 退出流程)
   ↓
引擎层 (爬虫.py ──→ 请求引擎 / 反爬检测器 / waf_captcha / 速度自适应 / sites_config)
   ↓                    ↓
内容层 (content_decoder / decrypt_utils / 内容质检器 → rust_core)
   ↓
状态层 (爬取历史 / 站点历史 / 风控事件 / 网站清单 / 书架 / 日志 / _path_utils)
```

**可选依赖的降级纪律**：所有第三方增强（curl_cffi / cloudscraper / ddddocr / playwright /
rust_core）均为**惰性探测 + 缺失静默回退**，缺任何一项主流程仍可运行（只是能力降级）。

## 7. 数据流程

### 7.1 抓取主流程（单任务）

```
create_task(url) ─► 守护线程 _run_task
   ├ 同域闸门 acquire（排队时日志显示 [排队]；stop 可打断等待）
   ├ run_crawl:
   │   域冷却检查（风控事件 delay_factor）
   │   → 章节目录（适配器 parse_catalog → 通用规则 → 自愈兜底）→ 排序
   │   └ 每章 worker（速度闸门 gate 控并发）:
   │        反爬识别循环（命中 → 退避/换引擎/UA轮换/WAF 求解/降档）
   │        → 提取（适配器 → 通用 4 模式 → 选择器自愈）
   │        → 解码（6 种）→ 清洗（零宽/广告行/段落去重）
   │        → 五维质检 → 通过则写盘；否则重试 → 仍失败存空占位（断点续传可补）
   │        → 爬取历史记录（SHA-256 指纹，增量依据）+ 风控事件打点
   │        → 任务事件.发布（进度/引擎/反爬/质检）→ TaskManager
   ├ 收尾（全路径必达）: 质检汇总报告 + 站点历史 + 网站清单 + 风控 task_result
   │                    + 漂移检测上报 + flush 各状态文件
   └ 闸门 release
```

### 7.2 反爬对抗链（分层防御）

```
响应 → 反爬检测器.识别(response)
  ├ rate_limit        → 指数退避(5/10/20/60) → 连续≥2 次写域冷却（als1010=900s）
  ├ waf_captcha       → (401/403/429 + __wafcaptcha 标记)
  ├ waf_verify_page   → (200 + 访问验证 + check_code + 页短<16KB)   ┐
  │                     两者进 WAF 分支:                              │
  │   ① solve_waf_captcha / _解_表单验证页 (ddddocr×5, 需显式开启)    ├→ 重取验证
  │   ② 失败/未开启 → solve_waf_captcha_manual (可见浏览器人工输入,   │
  │      每任务最多 1 次) → cookie 回灌 session                        ┘
  ├ waf_js_challenge  → 浏览器渲染取动态令牌（cloudscraper 优先）
  ├ js_cookie         → 提取校验 cookie 重试
  └ ua_block          → UA 轮换（内置 21 UA 池，按域 hash 稳定）
所有命中: 风控事件 JSONL 打点 + 速度自适应 note_risk 即时降档
```

### 7.3 GUI 数据流（已脱离日志文案依赖）

```
爬虫线程 ─结构化事件(contextvars, 主数据源)─► TaskLogRedirector.处理任务事件 ─► TaskInfo/TaskMetrics
        └print ─────────────────────────────► task.logs（仅展示，正则兜底已停用）
GUI 刷新循环（1s，主线程）─读 TaskManager─► 子树级 update
内嵌远控（SSE/REST）────读同一 TaskManager ──► 手机面板
（异常回退：TaskLogRedirector.启用正则兜底 = True 一行恢复旧行为）
```

### 7.4 退出流（7 步，顺序不可改）

停远控 → 停托盘 → 运行中任务置 stop_flag 等检查点（≤3s）→ 收尾钩子（显式 flush，
因 `os._exit` 不跑 atexit）→ destroy 窗口 → 等 1.5s → 强制结束。

## 9. 开发规范

### 9.1 修复工作流（强制顺序）

1. 改代码 → 2. **为该修复补回归用例**（离线，用 `测试样本/` 快照）
2. `python -m unittest discover -s 测试` 全绿 → 4. `python 脚本/check_undefined_refs.py` 无新告警
3. 更新 `CHANGELOG.md`（对齐既有条目格式）→ 6. 提交信息格式 `fix(域): 一句话` / `feat(域): ...`（中文）

### 9.2 编码硬规约

| 规约 | 要点 |
|---|---|
| 原子写 | 凡写 JSON 状态文件必须 tmp + `os.replace`，配防抖 + `flush()`/`atexit` 兜底；**禁止**直接 `write_text` |
| 裸 except 留痕 | `except Exception: pass` 禁止；至少 `_log.debug(f'裸 except 吞异常: {type(e).__name__}')`；有意静默须逐行注释原因（`test_no_silent_except` 执法） |
| SSRF 防护 | 一切用户可控 URL 发请求前过 `validate_public_url` |
| 线程安全 | 爬虫工作线程只写数据结构，绝不碰 Flet 控件；共享可变状态加锁或放 thread-local |
| 资源释放 | driver/session 提供 `close()`/幂等清理，支持 with 上下文 |
| 双实现同步 | 质检权重/阈值改动须同步 `rust_core_poc/pyo3_ext/src/lib.rs` 并跑 `qa_parity.py` |

### 9.3 文件上传规约（2026-09-13 定稿，见 AGENTS.md）

- **入库白名单**：`源码/ 测试/ 站点适配/ 脚本/ 测试样本/ 文档/ 配置/(模板) .github/ 界面设计预览/` + 根级元文件
- **禁止入库**：运行时用户数据（`数据/*`、`抓取结果*`、`日志/`、根级两份配置、`HANDOFF.md`）、
  会话私有目录（`.workbuddy/ .zcode/ .idea/ .mimosa/ .trae/ .vscode/`）、
  编译打包产物（`dist/ build/ target/ *.spec build_log.txt *.zip`）、大体积工具链
- **提交纪律**：`git add` 必须指定路径（禁 `-A`/`.`）；提交前 `git status -s` 逐行确认无他人
  在途文件；>1MB 二进制入库先说明用途
- **门禁知识**（Mimosa git hook，2026-09-26 实证）：commit 前实扫工作区，存在 high 即硬拦
  （与是否存量无关）；**扫描含 .gitignore 已忽略文件** → 第三方/工具链产物不要放项目树
  （Flet 客户端缓存已因此移出至 `%LOCALAPPDATA%\小说爬虫\构建缓存\`）

### 9.4 方法论沉淀（多轮实证）

- 批量改动走"**干跑审查 → 备份 → 落盘 → 效果证据**"四步（曾出现测试全绿但写盘失败的假绿）
- 判断存在/不存在一律 **AST / 全文检索**，子串匹配会误判
- 换测量方法先证明它**真能观测到目标**（探针扰动、插桩未接观测点、小样本外推均踩过）
- 改前先 grep 复核现状（历史结论会过期，也会出错——台账自身曾有两处误判）
- 多会话并行：**删除产物/状态前务必确认归属**（曾有误删真实爬取产物事故）

## 11. 技术难点与潜在风险

### 11.1 已克服的核心技术难点

| 难点 | 解法 |
|---|---|
| 站点反爬手段多样且演化 | 无状态特征驱动识别（不硬编码域名）+ 分层降级 + 人工兜底，新机制按枚举扩展 |
| **200 状态码的内容型 WAF 拦截页**（状态码层无法识别） | 双标记 + 页长阈值的内容特征机制 `waf_verify_page`（09-12 实网取证定案） |
| GUI 状态与爬虫耦合（日志文案成隐式协议） | contextvars 结构化事件通道替代正则解析（含"并行失明"修复史） |
| flet 双进程退出留孤儿窗口 | 7 步退出流程（destroy → 等待 → 强制结束），顺序不可改 |
| CPU 热点受 GIL 串行 | Rust PyO3 + `py.allow_threads` 释放 GIL（解码 ~13x、质检 ~11x，并发再 ×3~5） |
| 多进程写同一 JSON 互相覆盖 | 落盘前无条件读盘合并（幂等只补缺失域，去 mtime 短路——曾致 CI flake） |
| 超长书失败重试拖成"卡死" | 重试间隔压缩 + 连续失败≥3 章跳过补试直接空占位（断点续传后补） |
| 站点改版静默失效 | 漂移检测 EMA 告警 + 选择器自愈启发式重定位（建议待审，不自动污染配置） |
| DNS 污染解析到 0.0.0.0 | 进程内 patch `getaddrinfo` + DoH 回退（含 DoH 源自身递归防护） |

## 附录 B：路径契约三级

| 常量 | 源码模式 | EXE 模式 | 存放内容 |
|---|---|---|---|
| `RESOURCE_DIR` | `源码/` | `sys._MEIPASS`（临时解包） | 只读内置资源（站点配置模板、ddddocr 模型、Flet client、rust_core.pyd） |
| `BASE_DIR` | 项目根 | EXE 所在目录 | 用户要直接看到/手改的（`抓取结果/`、`站点适配/`、`站点配置.json`、`captcha_config.json`） |
| `STATE_ROOT` | `%LOCALAPPDATA%\小说爬虫\` | 同 | 使用痕迹（历史/书架/风控/日志/进度），换 EXE、重装不丢，首次运行自动迁移旧数据 |
