## 二、H1：U19 事件通道并行模式失明（本轮最重要发现）

### 事实链（全部回源头核验）

1. **订阅方存储是 threading.local**：`源码/任务事件.py:32` `_线程槽 = threading.local()`。
   订阅发生在任务子线程（`task_manager.py:609` `任务事件.订阅(重定向器)`）。

2. **发布点一半在 ThreadPoolExecutor worker 线程**：并行抓取（threads>1）时
   `爬虫.py:6188` `pool.submit(_ctx_mod.copy_context().run, worker, ...)`，
   worker = `_fetch_chapter_worker` → `_fetch_with_qc`（**质检事件** 爬虫.py:5553/5557）
   → `get_chapter_content` → `_get_with_js_challenge_impl`（**引擎成功/失败、反爬、
   WAF 验证码/JS 挑战事件** 爬虫.py:1001-1093）。这些发布点全部运行在 worker 线程。

3. **threading.local 不随 copy_context 传播**：`copy_context()` 只复制 contextvars，
   worker 线程访问 `_线程槽` 得到**空存储** → `发布()` 无订阅方 → **事件静默丢弃**。
   对照：`_ThreadAwareStdout` 用的是 `_WRITER_CTX = contextvars.ContextVar`
   （task_manager.py:416），worker 里的 **print 正常路由回任务**——所以
   任务事件.py 文档里"与 _ThreadAwareStdout 的线程模型一致"的说法**不成立**，
   两者机制不同，恰是事件通道断掉而旧正则通道不断的原因。

4. **正则兜底已默认停用**：`task_manager.py:90` `启用正则兜底 = False`（U19 二阶段）。
   于是并行模式下**没有任何通道**更新以下 GUI 指标：
   - `metrics.engine`（引擎列）
   - `metrics.engine_fallback_chain`（降级链列）
   - `metrics.anti_spider_type`（反爬列）
   - `metrics.quality_score/passed`（质检列，运行中；完成时 `_backfill_quality`
     从站点历史回填，是唯一的部分兜底）
   进度/总数/标题/输出文件/增量跳过事件在任务线程主循环发布（爬虫.py:6180/6225/6281/6292），不受影响。

### 为什么没被发现

- `测试/test_event_end_to_end.py` 无 threads/并行覆盖（grep 零命中）；
- U19 真实运行差分（322zw.com 51 章，事件生效 54 次）是串行模式；
- 串行模式全链路在任务线程内发布，threading.local 正常可见。

### 影响面

所有 GUI 并行抓取任务（线程数>1）的引擎/降级链/反爬/实时质检列不更新。
非崩溃、非数据损坏，属**信息展示失明**，但用户无感知路径、难自查。

### 修复方案（精准小改，约 10 行）

`任务事件.py` 把 `threading.local` 换成 `contextvars.ContextVar`（与 `_WRITER_CTX`
同机制）：

```python
import contextvars
_订阅方槽 = contextvars.ContextVar('任务事件_订阅方', default=None)

def 订阅(接收方) -> None:
    列表 = _订阅方槽.get()
    if 列表 is None:
        _订阅方槽.set([接收方])
    elif all(接收方 is not x for x in 列表):
        列表.append(接收方)
# 退订/有订阅方/发布 同步改读 _订阅方槽.get()
```

- 任务线程订阅 → `copy_context()` 快照含订阅列表 → worker 里 `发布()` 可见；
- 线程隔离语义保持：新起裸线程 default=None 收不到（现有
  `test_event_channel.py` 的隔离用例不破）；
- CLI 无订阅方：`get()` 返回 None，零成本不变；
- 退订在 `_run_task` finally（线程池 with 块已退出后），无竞态。
- 回归测试：补"copy_context().run 内发布 → 订阅方收到"用例（现有测试全部只测线程隔离，
  恰是漏掉传播语义的地方）。

回滚：还原 threading.local 即一行。

  增量元数据非正文）。可给快照配版本号、replace 前校验最新。
