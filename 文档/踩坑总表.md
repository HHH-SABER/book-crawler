## A. 环境与工具链

### K1 · 本机 bash 缺 coreutils，管线必然失败
- **症状**：`dirname: command not found`、`tail: command not found`，退出码 127；或代码看似执行了却**没有输出**。
- **原因**：本环境 bash 的 PATH 里**没有** `ls/tail/head/cat/env/grep/dirname`（连 `env` 都没有）。
- **规避**：
  - 文件列举/搜索/读取一律用 **Glob / Grep / Read 工具**，不要用 shell 命令；
  - 需要跑 Python 时用 `./.venv/Scripts/python.exe`（项目 3.14）或
    `C:/Users/18266/.workbuddy/binaries/python/versions/3.13.12/python.exe`；
  - 需要"剥代理"等 env 操作时，**不要**用 `env -u`（env 不存在），改用 Python `subprocess` 改 env 字典；
  - 探针/脚本的输出**优先写文件再用 Read 读**，别指望管道。

### K2 · 安全删除钩子**按轮计额**，大批量清理会废掉本轮所有删除
- **症状**：删几百个文件后，**连删单个文件**都被拒；`SAFE_DELETE_BULK_CONFIRM_REQUIRED`（阈值 50 项/轮）。
- **原因**：环境钩子按**本轮对话累计**删除量限额；额度耗尽后 PyInstaller 覆写 exe、清 `build/` 全部失败 → 打包中止。
- **规避**：
  1. **顺序**：先打包/推送，**再**清理；或分两轮做；
  2. 打包时置 `WBC_SKIP_CLEAN=1`，并把旧 `dist/*.exe` **改名**让位（改名不触发额度，`发布流程.py` 已内置）；
  3. 删目录用 `shutil.rmtree` 提前做；实在删不掉就留给用户手动删，别硬刚。

### K3 · `git push` 被注入的代理拖挂
- **症状**：push 挂起或 502，而 `git ls-remote` 正常。
- **原因**：环境注入的 `http(s)_proxy` 对大连接不稳。
- **规避**：剥离代理后推送 —— `脚本/发布流程.py` 已内置该逻辑（Python 改 env 字典 + `GCM_INTERACTIVE=none`）。
  另注意：`refs/remotes/origin/main` **不会自动更新**，必要时手动 `git rev-parse HEAD > .git/refs/remotes/origin/main`。

### K4 · 沙箱提权对删除钩子无效
- **症状**：`dangerouslyDisableSandbox` 后仍被同一钩子拦。
- **原因**：该钩子**不在沙箱层**，提权绕不过。
- **规避**：按 K2 的时序安排，不要指望提权。

### K5 · pip 后台中断留下残损目录
- **症状**：venv 里出现 `~xxx` 目录 / import 报奇怪错误。
- **规避**：删掉残留或 `pip install --force-reinstall`。
  另：`ddddocr 1.6` 新架构（compat/core）模型引用链不透明，**勿随意裁剪 onnx 模型**。

## B. 构建与发布

### K6 · PyInstaller 覆写旧 EXE 会被拦
- **症状**：构建在 `Copying bootloader EXE to ...dist\小说爬虫.exe` 前后失败。
- **原因**：它覆写前会先删目标文件，撞上 K2 的额度。
- **规避**：构建前把旧 `dist/*.exe` **改名**（`发布流程.py:_挪开旧产物` 已做，成功即删备份、失败还原）。

### K7 · 版本号与 CHANGELOG 会被构建消耗
- **原因**：`build_exe.py` 成功时 +1 版本并改 CHANGELOG。
- **规避**：**门禁必须前置于打包**（`发布流程.py --仅门禁` 只跑 ①②③，不碰版本号）。

### K8 · "步骤报绿但产物不对" —— 被吞掉的失败
- **实例**：`release.yml` 里 Rust 编译路径写成 `rust_core_poc/.venv`（实际在仓库根），
  失败被 `|| { echo WARN; exit 0; }` 吞掉 → **每次发布的 EXE 都没有 Rust 加速**，且 CI 全绿。
- **规避**：①**别信"已修"结论，要实测**（前一轮台账曾声称该项已修，实测未修）；
  ②CI 里禁止用 `|| exit 0` 掩盖构建失败——要么真失败，要么显式标注降级原因。

### K9 · 冒烟测试的两种误判
- **症状**：EXE 起不来却判"通过"；或你的桌面窗口在测试时被杀。
- **原因**：旧判据是 `"flet.exe" in tasklist`（**残留进程**会让它假通过），
  且 `finally` 用 `taskkill /IM flet.exe`（会**误杀用户正在用的 GUI**）。
- **规避**：用 **PID 差分**（只认启动后新出现的 PID），清理只回收本次拉起的进程
  （`build_exe.py:_flet_pids`）。跳过冒烟必须判为**失败**，需显式 `--allow-skip-smoke` 才放行。

### K10 · Rust 与 Python 必须**双端同改**
- **原因**：`内容质检器.py` / `content_decoder.py` 与 `rust_core_poc/pyo3_ext/src/lib.rs`
  逻辑**严格镜像**，`测试/test_offline_parsing.py::TestRustFallbackParity` 断言两路结果全等。
- **规避**：改判定语义时**两端一起改**；改 Rust 还要**重建 `源码/rust_core.pyd`**（本地需先装 maturin）。
  只改一侧 → parity 测试红，或线上两条路径行为不一致。

## C. 运行时与并发

### K11 · flet 桌面是**双进程**，退出顺序不能改
- **症状**：界面还在、后端已死、点关闭没反应（"关不掉/卡死"）；或 Python 挂住不返回。
- **原因**：Python 侧是 Flet 协议服务端，Flutter 客户端 `flet.exe` 是**独立子进程**。
  `os._exit()` 不跑 finally/atexit → 留下**孤儿窗口**；只用 `page.window.destroy()` → `ft.run()` 不返回。
- **规避**：统一走 `源码/gui_components/退出流程.py` 的 `执行退出()`（**7 步顺序不可改**：
  停远控→停托盘→置位等检查点→显式落盘→destroy→等 1.5s→兜底强退）。
  注意 `page.window.close()` 配 `prevent_close=True` 会被再拦，不能用它退出。
  另：无 atexit 兜底 → 退面前必须**显式 flush**（爬取历史/站点历史/风控事件）+ 关日志。

### K12 · 导入期的全局副作用会雪崩式拖挂测试
- **症状**：一堆**看似无关**的测试同时失败（含远控 uvicorn 绑定端口）。
- **原因**：`爬虫.py` 在**导入期**调用 `dns_doh.install()` 给 `socket.getaddrinfo` 打全局补丁；
  `unittest discover` 会先导入所有测试模块 → 补丁在全进程生效 →
  以 `socket.getaddrinfo` 当"原函数"的代码**无限递归**。
- **规避**：①看到"多个无关失败"**先怀疑全局补丁**，别分头排查；
  ②已根因加固（`dns_doh._真实_getaddrinfo` 固定引用导入时快照）；
  ③新写测试**避免在导入期产生全局副作用**。

### K13 · 状态文件被**两个进程**整文件覆盖
- **症状**：`爬取历史.json`(440KB) / `站点历史.json` 丢记录，或 JSON 损坏。
- **原因**：GUI 与远控是**两个进程**，各持内存副本整文件覆盖；共用 `.tmp` 还会互相截断。
- **规避**：已做两级防护 —— ①临时文件名带 **pid**；②写前比对 mtime，被外部改过则**按顶层键合并**。
  **残留**：同一域名两端并发更新仍是"后写覆盖先写"（逐条合并需变更追踪，属独立设计项）。

### K14 · 持锁做文件 IO 会拖死并发
- **规则**：单文件 **> ~100KB** 的状态落盘一律"**锁内取快照 → 锁外原子写**"（爬取历史/站点历史已改）。
- **反面**：0.7KB 级的 `域状态.json`、`站点基线.json` **别改** —— 锁内 IO 是微秒级，
  动它只会破坏 mtime 守卫缓存语义。

### K15 · GUI 数据通道的真实构成
- `print` 与 `_log.info` **都能**进 `TaskLogRedirector.write()`，但**前提是 `日志.enable_console()` 已启用**
  （`run_crawl` 会自动启用；未启用时 `_log.info` 只写文件、不进 GUI 解析器）。
- **2026-09-11 起（U19）**：GUI 的运行时数据改由 **`源码/任务事件.py` 结构化事件**驱动，
  日志正则通道**默认停用**（`TaskLogRedirector.启用正则兜底 = False`，一行可回退）。

### K16 · `TaskLogRedirector(task, None)` 会吞掉你自己的输出
- **症状**：实验脚本打印不出任何东西。
- **原因**：`write()` 末尾要把文本回显到 `original`，传 `None` → 抛异常被 `except` 吞掉；
  而若脚本已把该重定向器注册为线程 stdout 写入方，**脚本自己的 print 也走进去被吞**。
- **规避**：传一个真 stdout（`sys.__stdout__`），或**先落盘再读文件**。

### 附 · 两条容易踩的隐式契约
- **task_id 不保证是纯数字后缀**：远控从 checkpoint 恢复的中断任务会写成 `resume_<md5>`
  → 任何 `int()`/排序/解析都必须容错（`task_manager._任务排序键`）。
- **日志文案曾是数据协议**：改任何契约文案都要同步 `测试/test_log_contract.py`。
  **U19 后此约束已解除**（正则停用），但契约测试仍保留用于回退通道。

## D. 测试与测量（本类最贵的教训）

### K17 · 探针会**扰动被测代码**
- **实例**：为统计解析次数而替换模块级名字（`crawler.BeautifulSoup`），
  **改变了名字查找** → 同一样本正文从 20996 字变 0 字，测量结论直接作废。
- **规避**：给**类自身**打补丁（如只包 `bs4.BeautifulSoup.__init__`），
  所有 `from bs4 import BeautifulSoup` 都指向同一个类对象 → 能计数且不改调用路径。

### K18 · 插桩得先证明"它真被调用"
- **实例**：插桩得出"正则兜底 0 次"，实为**没把重定向器注册为线程 stdout 写入方**，
  `write()` 压根没被调用 → 这个 0 是**构造出来的**。
- **规避**：换测量手段时，**先加一个已知会命中的样本验证观测点**，再信数字。

### K19 · 别从样本前几条推断分布
- **实例**：从 3 行日志样本断言"某日志行不存在"，**全文检索后发现它出现 128 次**。
- **规避**：判断"存在/不存在"一律**全文检索**（Grep），抽样不能代表分布。

### K20 · 证明测试**不是空过**（反向对照）
- **做法**：把待验证的通道关掉/退订，重跑同一流程，**断言状态确实为空**；
  再对比正向断言的值与**默认值**不同。
- **实例教训**：反向对照脚本第一版判据写成 `not 任务.title`，
  而 `TaskInfo.title` 的默认值是字符串 **`'未知'`** 而非空串 → 误报"状态被别的东西填上了"。
  **验证脚本本身也要先核对默认值语义。**

### K21 ·警惕**自证式误读**
- **实例**：为"能否删除正则"设计的诊断，在正则被关掉后必然报"改写 0 次"，
  原逻辑据此输出"覆盖完整，具备删除正则的条件" —— **用关掉的开关证明开关可以删**。
- **规避**：指标设计时想清"这个 0 是**观测结果**还是**配置产物**"，并把口径写进 docstring + 测试守着。

## E. 协作与流程

### K22 · 并行会话 + `git add -A` = 误提交别人的文件
- **实例**：把仓库根的 `HANDOFF.md`（**另一个 Agent 的在途交接文件**）一起提交并推送。
- **规避**：**提交前先 `git status -s` 逐个确认是不是自己的改动**；不确定就用 `git add <路径>` 点名添加。
  `CHANGELOG.md` 归并行会话管，别重复添加。

### K23 · 历史"死代码清单"不可信
- **实例**：一份 6 项清单里 **2 项其实在用**（`icon_rail.toggle_theme_icon` 被 gui_app 调用、
  `ui_fluent.make_morandi_card` 被 remote_page 导入）、1 项是文档化的紧急开关；
  **照单直删会直接 ImportError**。
- **规避**：涉及**删除**与**语义变更**前，一律**回源头 grep 复核**。

### K24 · `HANDOFF.md` 是跨 Agent 交接文件（不入库）
- **约定**：任意 AI Agent（zCode / WorkBuddy / Claude Code / Cursor…）交替开发用；
  **开工先读、每完成一个可交付单元就更新动态信息区**，禁止攒到最后写。
- 已被 `.gitignore` 忽略（历史 `16c5372` 留有未填写的模板，无敏感信息）。

### K25 · 敏感信息
- `数据/远控配置.json` **含 token** —— 勿写入任何文档、交接文件或聊天。
- 调试打印配置时只打印**键名**，不要打印值。
