## 一、P0 — 严重（会造成实际数据错误，优先修复）

### P0-1 断点续传检查点与输出文件缓冲不一致 → 崩溃后续传可能跳章

- **位置**：`源码/爬虫.py` L4956-5036（run 方法写入循环）
- **问题**：每章写入 `f.write(...)` 后立即调用 `_save_checkpoint(...)`。但输出文件句柄是**带缓冲**的，检查点却立即落盘。若进程在写入后、缓冲区刷盘前崩溃/断电：检查点显示"第 N 章已完成"，但该章内容实际未写入磁盘。下次续传从第 N+1 章开始 → **该章永久丢失**。
- **影响范围**：所有使用断点续传的抓取任务；异常中断概率虽低，但一旦发生就是静默丢章，用户难以察觉。
- **方案**：在 `_save_checkpoint` 调用前插入 `f.flush()`（约 3 处调用点），确保内容先于检查点落盘。改动 5 行以内，无兼容性风险。

## 二、P1 — 高优先级（显著影响可靠性/安全性/可维护性）

### P1-1 全局禁用 TLS 证书校验

- **位置**：`源码/爬虫.py` L390 `self.session.verify = False`；L30 `urllib3.disable_warnings(...)`
- **问题**：所有 HTTPS 请求不验证服务端证书，抓取内容可被中间人篡改（正文注入、重定向劫持）。全局 disable_warnings 还把其他真实告警一起吞了。
- **影响范围**：全部 requests 通道的请求。
- **方案**：默认 `verify=True`；仅当配置文件 `captcha_config.json` 中显式设置 `"disable_tls_verify": true` 时才关闭（少数站点证书链确实有问题的场景）。同时移除全局 disable_warnings，改为按需局部告警过滤。

### P1-2 GUI"停止"按钮在并发模式下会长时间无响应

- **位置**：`源码/爬虫.py` L4981-4983（并发抓取分支）
- **问题**：点停止后 `return output_file` 位于 `with ThreadPoolExecutor(...)` 块内，解释器退出时会 `shutdown(wait=True)` **等待所有已提交的章节任务跑完**；而 worker 内部未检查 stop_event（全文件仅 3 处 `is_set()` 检查点，都在主循环）。几百章的书点停止后会继续请求几十秒甚至几分钟。
- **影响范围**：GUI 并发抓取（threads>1）时的停止操作；串行模式正常。
- **方案**：① `_fetch_chapter_worker` 开头增加 `if stop_event and stop_event.is_set(): return ''`；② Python 3.9+ 可用 `pool.shutdown(cancel_futures=True)`。两处合计约 10 行改动。

### P1-3 NovelSpider 缺少资源清理方法 → Chrome 进程/临时目录泄漏

- **位置**：`源码/爬虫.py` L352 NovelSpider 类（无 `close()/__exit__`）；L429 `tanmixs_chrome_profile` 临时目录
- **问题**：持久化 Selenium driver 只在少数正常路径 quit（L552/594/885/928）。GUI 停止任务、抓取异常中断时，Chrome 进程和临时 profile 目录会残留在系统里，反复停止/重启后进程堆积、临时盘占满。
- **影响范围**：所有涉及 Selenium 兜底的任务（tanmixs 等强反爬站点）。
- **方案**：给 NovelSpider 加 `close()`（quit driver + 可选清理 profile）和 `__enter__/__exit__` 协议；GUI task_manager 的任务收尾处统一调用。

### P1-4 巨型文件与巨型方法：爬虫.py 5,762 行，get_chapter_content 1,346 行 / get_chapter_list 1,271 行

- **位置**：`源码/爬虫.py`
- **问题**：单文件混合了 HTTP 引擎、WAF 识别、4 种正文模式解析、清洗、检查点、质检报告、CLI 菜单等 7 类职责。两个 1,300 行方法内含大量按站点分支的 if/elif，改任何站点都可能碰坏其他站点。
- **影响范围**：全部核心功能的可维护性与回归风险。
- **方案（渐进式，不必一次到位）**：
  1. 第一步：把 `get_chapter_list` / `get_chapter_content` 中按 PATTERN 分支的逻辑抽为独立函数（签名保持稳定），目标是两个方法降到 300 行以内；
  2. 第二步：把"清洗"（clean_content、去重、广告过滤）拆到 `清洗.py`；
  3. 第三步：CLI 菜单（interactive_menu 等，约 600 行）拆到 `命令行界面.py`。

### P1-5 零自动化测试

- **位置**：全项目；`脚本/_test_gui_v3.py`、`_test_task_metrics.py` 是临时手测脚本
- **问题**：三轮重构（4977→4440→5762 行的多次演变）都靠端到端手测，解析逻辑一改就有静默回归。
- **方案**：利用现成的 `测试样本/`（16 个 HTML + 3 个 JS）建离线回归：断言"给定该 HTML → 提取出 N 章、首章标题为 X、正文含特征串"。不联网、跑得快，先覆盖 4 种正文模式各 1 个站点。工作量约 1 天。

### P1-6 异常吞噬面过大：248 处 `except Exception` + 约 51 处静默 `pass` + 3 处裸 `except:`

- **位置**：全项目，重灾区：爬虫.py（25 处 pass）、gui_app.py（8 处）、日志.py（6 处）；裸 except 在爬虫.py L1991/2377/2398
- **问题**：配置读失败、站点解析失败、保存失败都被静默吞掉，出问题时日志里没有任何线索。
- **方案**：分三档处理——① 纯数值解析类的裸 except 改为 `except (ValueError, TypeError)`；② 静默 pass 至少加 `logger.debug(...)` 记录；③ 裸 `except:` 全部改为具体异常类型。可分批进行，先改裸 except（3 处）。

## 三、P2 — 中优先级（性能/依赖/健壮性）

### P2-1 依赖清单问题：httpx 声明未使用、opencv 双装

- **位置**：`requirements.txt` L9-10（httpx/httpcore）；venv 中 opencv-python 与 opencv-python-headless 同时安装
- **问题**：① 源码 0 处 import httpx（仅 flet 传递依赖需要，不必显式声明）；② 两个 opencv 包都提供 cv2，存在安装顺序冲突隐患，且打包 EXE 体积白白多 60MB+。
- **方案**：requirements.txt 删除 httpx/httpcore 两行；卸载 opencv-python 只保留 headless（验证码模块只用图像处理，不需要 GUI 功能）。

### P2-2 fake-useragent 初始化无降级保护

- **位置**：`源码/爬虫.py` L391 `self.ua = UserAgent()`（无 try 包裹）
- **问题**：fake-useragent 某些版本初始化时会联网拉取浏览器数据，离线环境或数据源失效时构造函数直接抛异常，整个 NovelSpider 无法创建。
- **方案**：包 try/except，失败时降级为内置的固定 UA 池（项目 headers 里已有一套完整请求头，可复用）。

### P2-3 日志体系依赖 stdout 重定向补丁，507 处 print

- **位置**：`源码/爬虫.py`（507 处 print，仅 1 处提及 logging）；CLI 在 `__main__` 里包 `_CliLogStdout`，GUI 在 task_manager 里用 TaskLogRedirector
- **问题**：两套重定向逻辑 + 大量 print，日志无级别、无结构，第三方库的输出也会混进来。
- **方案**：长期统一到 `logging`（每模块一个 logger，CLI/GUI 各配 handler）。短期内可接受现状，但新代码不要再加裸 print。属于"还债型"改动，排在高优重构之后。

### P2-4 6 个依赖小版本落后

- **位置**：requirements.txt / venv
- **明细**：beautifulsoup4 4.14.3→4.15.0、lxml 6.0.2→6.1.2、onnxruntime 1.28→1.29、playwright 1.58→1.62、requests 2.32.5→2.34.2、selenium 4.46→4.48
- **方案**：常规 `pip install -U` 后跑一轮端到端验证即可，均为小版本，风险低。flet 0.86.5 保持锁定（API 变动频繁，升级需专门回归）。

### P2-5 双浏览器自动化栈（selenium + playwright 并存）

- **位置**：requirements.txt、browser_driver.py、爬虫.py 多处
- **问题**：两套浏览器引擎都进 EXE，打包体积显著增大；但两者分别服务不同站点模式（tanmixs 用 selenium 持久 profile，其他用 playwright），立即裁剪有回归风险。
- **方案**：暂不裁剪。在 P1-5 的离线回归测试建立后，再评估把 playwright 场景迁到 selenium（或反向），单栈可省 80-100MB 体积。

### P2-6 检查点兜底逻辑依赖 `## ` 前缀计数

- **位置**：`源码/爬虫.py` L4639-4645 `_count_written_chapters`
- **问题**：用 `line.startswith('## ')` 数章节，若正文中出现以 `## ` 开头的行（清洗逻辑误放行）会虚增计数，导致续传跳章。
- **方案**：在 clean_content 中过滤/转义正文里的 `## ` 开头行；或计数时同时校验上一行为空行。
