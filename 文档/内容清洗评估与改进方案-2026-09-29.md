## 1. 现状评估（改进前基线）

### 1.1 架构总述

清洗体系为**三层结构**，无独立模块（全部埋在 `源码/爬虫.py` 约 7300 行上帝类中）：

```
┌─ 第一层: 提取端正点 ── 4 条提取链 (数据文件/适配器/站点配置/通用) 各自 get_text
├─ 第二层: clean_content 流水线 (~200 行, 11 步: 零宽字符→拼音噪声→乱码转义→
│          水印→HTML实体→误纠表→页码→行级过滤(关键词/URL/过短/符号/广告)→
│          短行合并→排版规范化→markdown前缀剥离) + deduplicate_paragraphs 去重
└─ 第三层: 五维质检闸门 (内容质检器.py: 有效长度25/中文占比25/乱码率20/重复率15/标点密度15)
           未通过 → 换UA重抓 → 仍失败存空占位 (质检只打分, 不反馈清洗)
```

### 1.2 规则资产盘点

| 资产 | 位置 | 形态 | 评估 |
|---|---|---|---|
| 广告结构正则 `_AD_LINE_STRUCT_PATTERNS` | 爬虫.py | 编译正则×N | 覆盖推荐列表/域名行/纯数字行, 有效 |
| 广告标签正则 `_AD_LINE_TAG_PATTERNS` | 爬虫.py | 编译正则×N(短行<40字) | 有效, 长行广告靠结构层 |
| 宣传语片段 `_AD_PHRASE_FRAGMENTS` | 爬虫.py | 字符串×~40 | 有效但**纯枚举**, 新站新话术需改代码 |
| 关键词整行过滤 `_CONTENT_FILTER_KEYWORDS` | 爬虫.py | 字符串×~35 | 导航/版权头尾覆盖广 |
| 水印 token `_WATERMARK_TOKENS` | 爬虫.py | 元组(1条) | 按站追加, 精确无误伤 |
| 错别字"修复"表 `encoding_fixes` | 爬虫.py | dict×48 | **含 9 条语义篡改级误纠**(见 1.4) |
| 站点差异化 `content_extractor` 枚举 | sites_config.py | yunquge_p_filter 等 5 种 | 每种都要写专用函数, **无可配置字段** |
| 五维质检 | 内容质检器.py | 阈值制+Rust加速 | 稳定, 无"清洗质量"维度 |

### 1.3 分段丢失根因（本次修复 7 处，均已提交）

| # | 位置 | 缺陷 | 修复 |
|---|---|---|---|
| ① | 爬虫.py Base64 解密链 3 处 | `get_text(strip=True)` 无 separator → 整章一行 | 补 `separator='\n'` |
| ② | sites_config.py 兜底最长容器 | 同上 | 同上 |
| ③ | clean_content 出口 | 删除全部空行, 段落边界**不可逆**丢失 | 按 `\n\n` 切段保留边界 |
| ④ | clean_content 短行合并 | <35字行无条件粘连 → 超长段 | 完整句后另起段, 宁过拆勿粘连 |
| ⑤ | pjxdd 专项清理 | `re.sub(r'\s+',' ')` 压扁 | 仅压行内空白 |
| ⑥ | 通用 Base64 兜底乱码清理 | `[\x00-\x1f...]` 连 `\n` 一起删 | 字符类排除 `\x0a` |
| ⑦ | 同分支行去重 | 空行被当重复项删除, `\n\n` 塌缩 `\n` | 空行不参与去重 |

> 排版侧同步: TXT 导出补齐"段首两全角空格 + 段间空行"（此前 EPUB 有缩进 CSS
> 而 TXT 无任何排版），增量搬运的旧正文经过 `_排版章节文本` 亦被重排为新格式。

### 1.4 主要局限（改进前）

1. **规则全部硬编码**：新增站点广告话术必须改爬虫.py 重发版; 站点差异化
   只能预置 `content_extractor` 枚举, 用户无法自助配置。
2. **误纠表含语义篡改**：`作对→作为`、`爆满→爆发`、`暴发→爆发`、
   `象限→相当于`、`在次→再次`（"生活在次元"误伤）等 9 条会改写正文原意;
   且存在 `渡假` 系列 17 条重复键与 9 条恒等映射（无效果条目）。
3. **链接处理一刀切**：整行含 `http(s)://` 或 `@` 即删行, 误杀
   "详情参见 https://... 这条帖子写得很清楚"类正文行。
4. **零可观测性**：清洗删了什么、删了多少, 无任何统计出口 —— 质检分低时
   无法区分"站点原文差"还是"清洗误杀"。
5. **无反馈闭环**：质检不回传"哪行被误清洗"; 站点漂移检测（EMA 空章率）
   与清洗规则之间无联动。
6. **段落边界在出口丢失**：下游（去重/质检/导出/增量搬运）拿到的是
   段落信息已抹平的文本, 任何后置修复都不可逆。

## 3. 智能化 Roadmap（按优先级, 均不引入新依赖/新网络行为）

### P1 · 误杀检测与规则反馈闭环（下一批次建议）

- **清洗-质检联动统计**: 质检报告中已有 `清洗统计`, 下一步把它纳入评分
  语义 —— 删除行占比异常（如 >30%）时在质检报告加"疑似过度清洗"标记,
  提示人工核对 (只告警不扣分, 避免误报影响自动判定)。
- **站点漂移联动**: 站点漂移检测 (EMA) 发现空章率突升时, 汇总该域
  最近 `清洗统计` 各维度计数, 定位是"站点改版"还是"清洗规则失效"。

### P2 · 规则自学习（离线约束内）

- **候选广告词自动收集**: 清洗删除的行已有类型计数, 可进一步把
  "同一域名高频删除行"去重抽样写入待审清单（复用 `选择器建议.json` 的
  原子写+人工审核模式, 方案A 不自动生效）, 人工确认后转为该域
  `ad_rules.关键词` —— 形成"删除→观察→审核→固化"闭环, 无需改代码发版。

### P3 · 清洗模块拆分（纯重构, 与 U20/U21 同批评估）

- `clean_content` + 规则常量 + 去重函数拆出 `源码/内容清洗.py`（~400 行）,
  爬虫.py 保持编排职责。收益: 规则可测性/可配置性/后续 Rust 化端口;
  代价: 动核心路径, 建议与"爬虫.py 上帝类拆分"统一立项。

### P4 · LLM 增强质检（可选云端增强, 默认关闭）

- 项目离线定位约束下, LLM 只能做**用户显式开启的可选增强**
  （对齐 `文档/实施计划.md §P7` 的定调）:
  质检低分章节可选送 LLM 判定"乱码/广告/正文"并给人工复核建议,
  **不进默认路径, 不自动改写正文**。

### 明确不做

- 基于大模型的正文自动改写/续写（离线与合规边界冲突）;
- 无人工审核的自动规则生效（防静默污染用户配置, 沿用选择器自愈方案A 的裁决）。

## 4. 质量评估标准（本次引入, 供后续回归）

1. **门禁**: `python -m unittest discover -s 测试` 全绿（当前 382）+
   `python 脚本/check_undefined_refs.py` 无新告警;
2. **分段**: clean_content 输出段落以 `\n\n` 分隔; 压扁输入经
   `重排历史TXT.py --dry-run` 后段落数显著增加且**字符数不变**
   （内容零丢失硬标准）;
3. **排版**: 段首恰两个全角空格、标题行不缩进、段间恰一个空行、
   幂等（跑两遍结果一致）;
4. **无误杀**: 含 URL 正文行保留剥离后文字（中文字≥10）; 高危词
   （"作对/爆满"等）不被误纠表篡改;
5. **可观测**: 任意一章清洗后 `_最近清洗统计.get()` 非空, GUI 任务详情
   可见清洗摘要; 事件契约（test_event_channel）双向断言不漂移;
6. **可配置**: `ad_rules` 关键词/行正则生效、非法正则跳过不崩、
   热重载后新规则即时生效。
