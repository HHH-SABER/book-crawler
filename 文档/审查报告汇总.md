## 08 · als1010 专项：批次分析 → 双层修复 → 实跑验收 — 2026-09-12（zCode）

> 触发：用户批次（11 URL）8 本书正文全空 + "用 EXE 跑成功率低"。

### 根因链（三层）
1. **触发**：GUI 批量逐 URL create_task 无同域限流（run_batch 有"同站 1 本"）
   → 8 本 als1010 并发 → WAF；
2. **识别缺失**：WAF"访问验证"页以 **HTTP 200** 返回（1475 字符，
   标题访问验证 + check_code 表单 + verify 图片），`is_waf_captcha_page`
   要求 401/403/429 → 识别不到 → 被当正文 → 清洗成空章（质检"中文占比 0%"）；
3. **EXE 低成功率（配置层）**：EXE 读 **EXE 旁** captcha_config.json
   （首启从合规模板复制，ddddocr 默认关）→ 自动识别被拒；源码读项目根配置
   （用户显式开启）→ 成功率高。两环境读两份配置。

### 修复（全部实测）
- 反爬检测器新机制 `waf_verify_page`（双标记+页短<16KB 防误伤）→ 命中自动
  记风控事件+速度降档；
- `is_waf_captcha_page` 扩展 200 同特征 → 进入爬虫既有 WAF 分支 → 人工兜底；
- **通用表单验证码自动求解** `_解_表单验证页`：实网取证该站 WAF 为会话 cookie
  制（无 UA 绑定），每轮重取被拦页取新图，提取图片/表单/隐藏域/输入框名，
  ddddocr 识别按原表单字段 POST，目标 URL 重取验证放行——**实网首轮识别即通过**；
  ddddocr 未开启明确拒绝转人工（合规边界不变）；
- `task_manager` 同域闸门：同站最多 1 任务（GUI/远控共享），排队 [排队] 可见，
  stop 可打断（自持自放）；
- 站点专项：SITE_TIER_CAPS als1010=0（1 线程压档）、域冷却 900s（软封实测
  24 分钟未恢复）、适配器识别"请稍后再试"软封页返回 None（旧行为提 342 字符
  垃圾致质检 62 分）；
- dist 配置对齐源码环境 + **发现"重打包清 dist 运行时配置"产品隐患**（见 07-L1）。

### 实跑验收（11 URL 全量两轮）
- 第一轮：7 本 100 分（含高冷妈妈 43/43 带 waf_verify_page×6 事件）、表单求解
  首轮实网通过（'dtn2'→放行）、人工兜底 4.5s 自愈（cookie×3 回灌）；
  3 本 als1010 未完——站点进入**长时软限频**（静默 24 分钟未解除，连续限频 58+）；
- 21:52 定时探针：仍封（2.8h+）→ 按守卫停止；
- 09-26 探针：**解封** → 全量重抓批次运行中（2 本完成，限频期行为正确）。
- 教训：同域限流必须与功能同步（GUI 批量缺失即放大器）；200 状态拦截页是
  "状态码检测"盲区，内容特征必须补位。

样本：`测试样本/als1010_访问验证页.html` / `als1010_软封页.html`；
测试：test_waf_verify_page ×5 / test_waf_form_solver ×3 / test_domain_gate ×5 /
test_als1010_site ×5。

## 03 · 全面审查与性能优化 — 2026-09-10（WorkBuddy）

> 每条结论回源头核实 + 实测度量（非估算）。

- 修复 5 项：任务列表排序崩溃（高危，静默瘫痪 GUI）/ GUI 日志解析热路径
  （实测 −95.5% 正则调用）/ CPU 基准锁一次性（正确性）/ 远控章节缓存并发
  淘汰（阅读页 500）/ 同页反复整页解码；新增回归 5 例。
- **性能核心结论**：**CPU 只占墙钟 4–11%，真正的瓶颈是网络等待**——最大单项
  开销是 `爬虫.py` 主路径每页硬编码 `time.sleep(random.uniform(0.5, 1.5))`
  （双重延迟，去掉会抬封禁率 → 需按站点灰度，未动）。已确认**不是**瓶颈：
  HTML 解析（实测 1.5 次/章）、正则、解码、排序——避免后人重复优化。
- 后续批次建议：站点灰度延迟、代理出口池。
